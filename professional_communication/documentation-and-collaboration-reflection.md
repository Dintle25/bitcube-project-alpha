# Documentation and Collaboration Reflection

## Reflection on README Evolution and Professional Communication

The original README made several assumptions:
- That anyone opening the repository already understood the purpose of the project.
- That readers knew what the Conference Room Booking System was supposed to do.
- That new developers would somehow figure out how to set up and contribute to the project.

The updated README improves onboarding significantly. I added a clear project overview, target users, system context, step-by-step setup instructions, project structure explanation, and a proper contribution workflow using Pull Requests. A new developer can now understand the project and start working on it much faster.

Through this assignment, I learned that Pull Requests and Issues are important communication tools. Writing a good pull request forces you to explain your thinking clearly, while well-structured issue templates help reduce back-and-forth questions. I now understand that good documentation and clear communication are essential in professional software development, not just nice-to-have features.
